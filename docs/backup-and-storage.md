# 完整备份与共享角色库 · 0.5.0

## 使用

打开宠物齿轮 → 完整设置 → **备份与恢复**。DSH 的插件设置也有相同入口。

1. 点击“导出完整备份”，保存 `dsh-bigfish-backup-日期.zip`。
2. 换浏览器或换机器后，在新 DSH 上安装 0.5.0 或更新的兼容版本。
3. 点击“选择备份恢复”。插件先检查 ZIP、每个角色的协议与实际图片、偏好和编排，展示角色数量与将使用的角色。此时不写入数据。
4. 核对后点击“确认恢复备份”。新增角色采用合并方式，原有角色保留；偏好和本浏览器编排使用备份中的值。

备份包括全部已安装角色版本及当前选择、行为和显示偏好、鞭策开关、自定义台词、工具规则、当前浏览器内置 JSON 编排。不包括聊天、模型密钥、速度学习缓存、宠物位置、首次问候冷却。限制为 32 个角色版本、128 MiB（ZIP、外层展开及所有角色的内部展开总和均受限）；每个 `.dshpet` 仍遵守 32 MiB、64 MiB 解压和角色协议的像素/帧上限。

备份来自角色库的同一时刻快照；偏好和浏览器编排是导出时读取的本地确认值，不构成跨所有窗口的数据库事务。备份中的内置角色以 `selected:null` 表示，素材由安装的插件提供。自定义文字和工具规则会进入备份文件，分享前请检查其内容。

## 冲突与失败

- 相同角色 ID、版本、内容可复用；相同 ID 和版本但内容不同，预览即拒绝，提示作者提升版本。不会覆盖现有角色。
- 预览记录目录 revision。其他 Host/窗口改动了目录，确认恢复会拒绝；重新选取文件并预览即可。
- 偏好也在实际写入时比较预览值，避免覆盖刚刚排队保存的设置。
- 角色包先写入，目录最后原子替换；多个新增包只在一次目录提交后出现。写入中断可能留下不在目录里的文件，它们不会作为角色加载。
- DSH 偏好、Host 角色目录和浏览器 localStorage 是三个存储域。恢复顺序为偏好 → 编排 → 角色目录；遇错尝试回滚前两项。如果其他窗口已修改偏好或编排，不覆盖它，界面明确报告未回滚的部分。
- 恢复期间应保持页面打开。断电、关闭页面或丢失 HTTP 响应无法保证跨存储域整体回滚；发生此类中断，重新打开设置核对，必要时重新恢复同一备份。角色导入可重复执行。
- 角色库 API 的内部快照没有完整用户偏好，不能冒充设置入口导出的完整备份。

## 共享 DSH_HOME

所有 0.5.0 Host 写入使用同一目录旁的心跳锁：先规范化真实目录路径，以原子建目录方式争抢锁，每 2 秒续期，10 秒无续期后可恢复。持锁进程正常退出释放；崩溃后等待过期恢复。导入解码在取锁前进行；提交前检查锁状态。读取备份也持锁，避免同时删除导致目录与文件不一致。

实现使用 [proper-lockfile](https://github.com/moxystudio/node-proper-lockfile)，版本固定在锁文件，MIT 许可附于第三方声明。单进程仍排队；不同浏览器的离线演示角色库改用 IndexedDB 的整批读写事务。

**共享同一 DSH_HOME 的所有 Bigfish 实例都需要升级。** 旧插件不认识新锁，不能保证与旧版本同时写入的安全性。本轮验证的是 macOS 本地文件系统及 Linux 容器文件系统；NFS/SMB、人工移动/删除锁目录未验证。请勿手动删除正在使用的锁目录。

## 数据路径

角色：`$DSH_HOME/pets/dsh-bigfish/`，缺省 `~/.dsh/pets/dsh-bigfish/`，同 Home 跨 profile 共用。

偏好由 DSH `bigfish` namespace 管理；本地编排键 `bigfish.pack.v1`；离线演示角色库 `dsh-pet-library`。更多范围见 [常见问题](faq.md)。卸载不删除用户角色和偏好。

包含命名空间冒号或 Windows 设备名前缀的角色 ID 使用可移植编码文件名，避免 NTFS 将冒号解释为数据流。普通既有文件名保持不变；POSIX 上旧的冒号文件仍可读取与移除。这个单元验证不等同于 Windows 原生运行验收。
