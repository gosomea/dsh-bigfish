# 功能测试与发布门禁

测试通过、界面验收、真实服务验收和正式发行分别记录。测试数量不能代替逐项功能验收；CI 绿灯也不代表 Windows、多屏、麦克风或签名已经通过。

## 可执行入口

| 命令 | 执行内容 | 能证明的范围 |
| --- | --- | --- |
| `pnpm verify:web` | 类型检查、重新构建、完整 Node 与 Chromium 回归 | 当前源码的逻辑、受控接口和 Web 交互。CI 执行同一组检查，不调用付费模型。 |
| `pnpm test:browser` | 先构建，再运行完整 Chromium 回归 | 不会测试留在 dist 中的旧界面。 |
| `pnpm test:desktop` | 先构建桌面 renderer，再运行 Electron 契约检查 | 本机真实 Electron 与临时 Host 契约；不是双平台实机验收。 |
| `pnpm release:verify` | 完整 Web 检查通过后生成 npm tarball、核对内容并记录源码／产物／日志指纹 | 当前源码与实际测试、安装包对应；失败不生成有效通过回执。 |
| `pnpm release:check` | 只读复核当前源码、包内容及通过回执 | 修改代码、测试、构建脚本或产物后，旧证据不能继续放行。 |
| `pnpm release:preview` | 复核完整 Web 回执和同一 tarball 的隔离 DSH 账本验证，再发布该 tarball 到 npm `next` | 只接受 `*-next.N` 版本。 |
| `pnpm release:formal` | 当前自动检查回执，加原生 Host 与正式双平台验收 | 缺少硬件、权限、签名或公证证据时返回非零。正常 `npm publish` 入口调用它。 |

自动化回执在忽略目录 `artifacts/companion/`，不能以手工改 `accepted` 或复制旧包来代替执行。手工验收仍需实际人员与设备；JSON 记录只是记录结果，不会自动证明硬件行为。管理员显式跳过生命周期脚本的命令不属于受保护的发布入口。

## 功能与证据

| 功能组 | 当前自动覆盖 | 仍需独立验收 |
| --- | --- | --- |
| 身体与活动 | `movement`、`clip-timeline`、`routines` 单元；`companion-clips`、`companion-living` 浏览器检查起停、边界、让位与末帧停留；`free-movement` 检查二维路线、真实步态、拖动、缩放与开工中止；活动区域检查全身碰撞、避障路线、不可达目标和回家点；素材逐帧证据 | 实际观看的连贯性、动作审美、物理多屏和长时间手感。 |
| 触摸与玩耍 | 互动事件、优先级、计数、成长锁与关闭分组；`life-programs` 浏览器演出；伙伴角色选择、素材就绪、角色缺失与生命周期隔离 | 真实触摸设备、不同角色素材的美术质量。 |
| 任务管家 | 账本、来源、通知去重、额度与预算；有限工具事实关联、裁剪与旧结果丢弃；原生 `smoke-ledger.ts`、`smoke-quota.ts` | 新包在目标 DSH 组合中的重新安装和实际事件验证；本地模型 fixture 不证明真实模型质量。 |
| 记忆与个性 | 工作区隔离、工具调用／结果来源引用、删除派生记忆、预算预留、过时回复、一次介绍；来源时间线区分事实与模型解读、未知旧时间及跨工作区来源 | 用户选择的真实模型服务、长期任务和多设备使用。 |
| 小窝与收藏 | 实际图层、主题、家具比例、角色状态与环境局部动态联动、安静／隐藏暂停、来源收藏、装扮与持久化 | 用户审美与不同角色的锚点制作。 |
| 成长与故事 | 真实互动次数、组关闭解除有效锁、虚构标记、故事和双宠行为链 | 长时间使用、真实纪念日和季节跨日体验。 |
| 桌面奇遇 | 受控场景、互斥／冷却、双宠组门控；桌面几何、显示坐标与首次放置／改大小竞态确定性回归 | Windows 实机、混合 DPI、拔插屏幕、真实睡眠恢复和系统窗口权限。 |
| 语音与感知 | 按住会话生命周期、取消、Host 切换、截图确认、模态与预算；原生 `smoke-screenshot.ts` | 真实麦克风、所选转写服务、OS 授权、实际声音和视觉模型质量。 |
| 设置与角色包 | 四页真实切换、真实 combobox／listbox、明暗主题与文字对比度、键盘／Escape 焦点、长清单滚动、屏边／锚点隐藏、牌文换行与省略；窄屏、关闭、草稿与错误；方案范围、旧格式兼容、并发保存／恢复与 Host 角色切换隔离；旧包／新协议校验与 Skill 对照；全局场景开关的实际像素、布置保留、旧偏好／方案迁移与共享 Host 持久化 | DSH 原生设置页的实际集成、跨平台控件和第三方角色包。 |

上述表格列出测试职责，不声明当前修改已经完成整轮验收。菜单测试使用真实可见的选项，不用隐藏的原生 select 代替；桌面位置测试可重现过渡坐标导致的跳顶，并检查目标坐标修复，不能代替真实 Electron 或物理多屏结果。

原生 Host 脚本只允许登记过的隔离 home，执行前检查身份和活跃任务，结束后停止自身进程；不会把日用 3080 作为测试实例。真实服务和硬件验收不能由 fixture、配置存在或交叉构建替代。

## 当前发行结论

`0.7.0-next.1` 是 Web 预览版。历史测试见[实施状态](plans/intelligent-pet/implementation-status.md)，当前源码的可复核结果以新生成的 release 回执为准。

“全能型 · 预览版”的功能状态按角色、配置和运行环境显示，与正式发行门禁分开。临时双宠可选择已安装角色，但仍限一名受邀伙伴，尚未提供数量配置。矩形允许区、禁行区和回家落脚点属于本设备设置；不随共享陪伴方案导入。

正式全能版目前仍被阻断：Windows 实机、多屏／DPI／真实休眠、麦克风与系统权限、有效签名和 macOS 公证，以及最终产物安装和录屏尚需验收。此前基础阶段通过记录是历史快照；新的源码指纹校验会拒绝不匹配的旧记录。
